# 需求说明

> 阶段 1 的交付物之一，已确认。

---

## 1. 定位

- **仅限个人使用，不公开。**
- **核心用途**：作为家庭 NAS 片源下载的决策依据——知道有哪些值得看的纪录片，哪些已经下载到 NAS，哪些还没有。
- **部署**：家中 NAS（树莓派）。

---

## 2. 两个独立的状态

一条作品同时有两个状态，互不影响：

| 状态 | 取值 | 含义 |
|---|---|---|
| **跟踪状态**（是否在范围内） | `待审核` / `已收录` / `已排除` / `观察中` / `待播` | 由跟踪流程和人工审核决定，见 `tracking.md` |
| **片源状态**（NAS 上有没有） | `未入库` / `计划中` / `已入库` | `计划中` = 想下载但还没下 |

- 只有 `已收录` 的作品才显示片源状态。
- `计划中` 手动标记；`已入库` 由 Jellyfin 自动同步（第 4.2 节），也可以手动改。
- **系列按季标记**：一部系列可能只下载了部分季，系列整体显示为 `部分入库`（如 “3/5 季已入库”）。长青栏目（*NOVA*、*Horizon* 等）按集标记。
- 纪录长片、YouTube 视频按单条标记。

---

## 3. 功能清单

### 3.1 浏览与筛选
- 按品牌、主题、年份、类型（系列 / 长片 / YouTube）、评分筛选和排序
- **按片源状态筛选**：`未入库`、`计划中`、`已入库`
- 中英文标题搜索

### 3.2 待下载视图（核心页面）
- `已收录` 且 `未入库` 或 `计划中` 的作品，默认按评分从高到低排列；`计划中` 可以单独筛出来作为下载清单
- 可按品牌、主题、年份进一步筛选

### 3.3 最近新出品
- 每个双周周期新收录的作品，带片源状态

### 3.4 详情页
- 作品信息、各来源评分（带拉取日期）
- 系列的季和集列表，每季/每集的片源状态
- YouTube 视频的原始链接

### 3.5 审核
- 待审核清单：逐条或按品牌/频道批量确认收录或排除

### 3.6 片源状态标记
- 手动标记：在列表页或详情页一键切换 `未入库` / `计划中` / `已入库`
- 自动同步：从 Jellyfin 读取媒体库，见第 4.2 节

## 4. 部署环境

### 4.1 树莓派现状

| 项目 | 情况 |
|---|---|
| 硬件 | Raspberry Pi 4，4GB 内存 |
| 系统 | Debian，已装 Docker |
| 已有服务（Docker） | Jellyfin、qBittorrent、Immich（不带 AI）、v2ray 代理 |

**内存预算**：4GB 里已有服务大约占 1.5–2.5GB（Immich 带数据库和缓存，Jellyfin 转码时会更高）。本应用的目标：
- 常驻（网页 + SQLite）控制在 150MB 以内
- 定时任务运行时峰值控制在 300MB 以内（IMDb 数据包逐行处理）
- 定时任务安排在深夜运行，避开观看和转码的时间

### 4.2 与 Jellyfin 集成

- Jellyfin 的 API 可以列出媒体库里所有作品，每部作品带 TMDB / IMDb 编号（刮削时写入的）。
- 用这些编号和本应用的作品对上，自动把片源状态改为 `已入库`，精确到季和集。
- 只读访问，不修改 Jellyfin 的任何内容。需要在 Jellyfin 后台生成一个 API key。
- 只按编号匹配，不按标题猜（阶段 2 决定，见 `source-mapping.md` 第 8 节）。没有编号的条目在未匹配页手动对应。

### 4.3 网络与代理

- TMDB、IMDb、YouTube 的访问需要走代理：采集任务通过 v2ray 提供的本地代理端口访问。
- 豆瓣、央视网等国内网站**直连**，不走代理（境外 IP 访问豆瓣更容易被风控）。
- 代理地址做成配置项，在你的电脑上测试时可以换成电脑上的代理。

### 4.4 测试与迁移

- **测试阶段**：在你的 Windows 电脑上**直接运行，不用 Docker**（装好 Python 即可），数据和配置都在本地。
- **迁移**：稳定后部署到树莓派，在树莓派上用 Docker 运行。你通过 Tailscale + SSH 远程操作即可，不需要在家。
- **镜像在树莓派上直接构建**：这样不需要做跨架构构建。迁移时只拷数据库文件和配置，代码不改。
- **为保证 Windows 和 Linux 两边行为一致**，开发时注意：
  - 路径统一用跨平台写法，不写死 `C:\` 或 `/` 分隔符
  - 所有文件统一 UTF-8 编码、LF 换行（仓库加 `.gitattributes`）
  - 所有配置（代理地址、数据目录、API key）放在配置文件或环境变量里，两边各一份
  - 定时任务：测试阶段手动运行；树莓派上用 cron 或容器内调度
- 测试阶段也可以通过 Tailscale 连接家里的 Jellyfin，提前验证片源状态同步。
- 不建议用 GitHub 托管运行：GitHub Pages 只能放静态页面，跑不了后端和定时任务；用 GitHub Actions 跑采集也可以，但数据要存到仓库或外部存储，比本地复杂。GitHub 只用来存代码。

### 4.5 树莓派上的部署约束

| 约束 | 应对 |
|---|---|
| ARM 架构 | 选用支持 ARM64 的技术栈和 Docker 镜像 |
| 内存有限 | 用 SQLite，不跑重量级数据库；IMDb 数据包逐行流式过滤，不整个读进内存 |
| SD 卡寿命 | 数据库和下载的 IMDb 数据包放在 NAS 硬盘或 SSD 上，不放 SD 卡 |
| 定时任务 | 用树莓派本机的定时任务（cron 或 Docker 内的调度） |
| 外网访问 | 只在家庭局域网内访问；需要在外面访问时用 VPN（如 Tailscale），不把端口直接暴露到公网 |

## 5. 主题标定与大模型

**主服务不依赖大模型。** 主题按 `scope.md` 第 6.1 节的顺序判断：先按频道/品牌分类，再按来源自带分类和关键词规则，最后人工审核。

**大模型标定作为一个独立的可选模块**，放在“关键词规则”和“人工审核”之间，减少人工审核量：

1. 主服务把还没有主题的条目**导出**成一个文件（标题、简介、来源、品牌/频道）。
2. 大模型模块读这个文件，给每条打主题标签和排除建议，输出结果文件。
3. 主服务**导入**结果，人工审核时作为建议显示。

这样大模型用哪种方式运行都可以替换，不影响主服务：

| 方式 | 需要什么 | 适合 |
|---|---|---|
| 网页版对话手动处理 | 你现有的 Claude Pro / ChatGPT Plus | 量小时：把导出文件分批上传到对话里，再把结果存回来 |
| **Claude Code 命令行**（推荐起步方式） | 你现有的 Claude Pro（Pro 包含 Claude Code） | 首次回溯和双周增量都可以：在 Windows 上让它读导出文件、写结果文件，受订阅的用量限额约束 |
| OpenAI Codex 命令行 | 你现有的 ChatGPT Plus（Plus 包含 Codex） | 同上 |
| Claude API | 单独开通 API，按量付费，和订阅分开 | 想完全自动化（定时任务里自动跑）时 |

- **订阅不包含 API**：Claude Pro、ChatGPT Plus 都是网页/应用/命令行工具的订阅，API 要在开发者平台单独开通、单独付费。
- **API 费用估算**：用最便宜的 Claude Haiku 5.5（每百万输入 token 0.10 美元，输出 0.50 美元），1 万条、每条约 400 token 输入、30 token 输出，总计**不到 1 美元**；用批处理接口还能再便宜一半。
- **不要用脚本自动操作网页版对话**：违反服务条款，也不稳定。
