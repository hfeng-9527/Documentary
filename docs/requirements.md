# 需求说明（草稿）

> 阶段 1 的交付物之一。已确认的写在前面，待确认的列在最后。

---

## 1. 定位

- **仅限个人使用，不公开。**
- **核心用途**：作为家庭 NAS 片源下载的决策依据——知道有哪些值得看的纪录片，哪些已经下载到 NAS，哪些还没有。
- **部署**：家中 NAS（树莓派）。

---

## 2. 两个独立的状态

一条作品同时有两个状态，互不影响：

| 状态 | 取值 | 含义 |
|---|---|---|
| **跟踪状态**（是否在范围内） | `待审核` / `已收录` / `已排除` / `观察中` / `待播` | 由跟踪流程和人工审核决定，见 `tracking.md` |
| **片源状态**（NAS 上有没有） | `未入库` / `已入库` | 是否已下载到 NAS 媒体库 |

- 只有 `已收录` 的作品才显示片源状态。
- **系列按季标记**：一部系列可能只下载了部分季，系列整体显示为 `部分入库`（如 “3/5 季已入库”）。长青栏目（*NOVA*、*Horizon* 等）按集标记。
- 纪录长片、YouTube 视频按单条标记。

---

## 3. 功能清单

### 3.1 浏览与筛选
- 按品牌、主题、年份、类型（系列 / 长片 / YouTube）、评分筛选和排序
- **按片源状态筛选**：只看 `未入库`、只看 `已入库`
- 中英文标题搜索

### 3.2 待下载视图（核心页面）
- `已收录` 且 `未入库` 的作品，默认按评分从高到低排列
- 可按品牌、主题、年份进一步筛选

### 3.3 最近新出品
- 每个双周周期新收录的作品，带片源状态

### 3.4 详情页
- 作品信息、各来源评分（带拉取日期）
- 系列的季和集列表，每季/每集的片源状态
- YouTube 视频的原始链接

### 3.5 审核
- 待审核清单：逐条或按品牌/频道批量确认收录或排除

### 3.6 片源状态标记
- 手动标记：在列表页或详情页一键切换 `已入库` / `未入库`
- 自动同步（如果 NAS 上用 Jellyfin，见第 5 节）

---

## 4. 部署约束（树莓派）

| 约束 | 应对 |
|---|---|
| ARM 架构 | 选用支持 ARM64 的技术栈和 Docker 镜像 |
| 内存有限 | 用 SQLite，不跑重量级数据库；IMDb 数据包逐行流式过滤，不整个读进内存 |
| SD 卡寿命 | 数据库和下载的 IMDb 数据包放在 NAS 硬盘或 SSD 上，不放 SD 卡 |
| 定时任务 | 用树莓派本机的定时任务（cron 或 Docker 内的调度） |
| 主题预判 | 调用大模型 API，不在树莓派上跑模型 |
| 外网访问 | 只在家庭局域网内访问；需要在外面访问时用 VPN（如 Tailscale），不把端口直接暴露到公网 |

---

## 5. 待确认

1. **树莓派的型号和内存**（如 Pi 4 / Pi 5，4GB / 8GB），系统是什么，是否已装 Docker。
2. **NAS 上用什么媒体服务器**（Jellyfin、Plex、Emby，还是只有文件夹）。
   - 如果是 Jellyfin / Plex / Emby：它们的 API 能读出媒体库里每部作品的 TMDB / IMDb 编号，可以**自动同步片源状态**，精确到季和集，不用手动标记。
   - 如果只有文件夹：可以按文件夹名匹配，准确率低一些，需要手动校正。
3. 片源状态是否需要更多取值，例如 `计划下载`（想下但还没下）。
