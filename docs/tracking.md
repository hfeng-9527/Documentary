# 双周更新跟踪方案

> 目标：**每两周**检查一次范围内各来源的新出品，生成一份待审核清单，人工确认后入库。

---

## 1. 跟踪什么

| 类型 | 说明 |
|---|---|
| 新作品 | 新的系列、单片、院线纪录片 |
| 新季 / 新集 | 已收录系列的新一季，长青栏目（*Horizon*、*NOVA*、*American Experience* 等）的新一期 |
| 已公布待播 | 已经公布播出日期但还没播的作品（能拿到就记录） |
| YouTube 新视频 | 范围内频道在本周期发布的、满足时长门槛的视频 |

---

## 2. 各来源怎么查

### 2.1 电视 / 流媒体品牌 → TMDB API（主要来源）

TMDB 免费提供 API，纪录片的分类 ID 是 `99`（电影和剧集都有）。

| 查询 | 用法 |
|---|---|
| 按播出方查新剧集 | `discover/tv?with_genres=99&with_networks=<播出方 ID>&first_air_date.gte=<上次检查日期>` |
| 按出品公司查 | `discover/tv` 或 `discover/movie` 加 `with_companies=<公司 ID>` |
| 已收录系列的新季/新集 | `tv/{id}` 看 `last_episode_to_air` / `next_episode_to_air`；或 `tv/changes` 拿变更列表 |
| 院线纪录片 | `discover/movie?with_genres=99&primary_release_date.gte=…&with_original_language=en|zh` |

- 各品牌对应的 TMDB 播出方/公司 ID 在建库时查好，存进配置表。
- **短板**：中文作品（央视、腾讯、优酷等）在 TMDB 上收录不全，见 2.3。

### 2.2 YouTube → YouTube Data API

- 用频道的上传列表（`playlistItems.list`）往前翻页，翻到上次检查的发布时间为止。
- **不用 RSS**：RSS 只返回最近 15 条，DW、National Geographic 这类高频频道两周内的上传可能超过 15 条，会漏。
- 批量取详情（`videos.list`），按时长门槛过滤。
- 配额：约 80 个频道，每次检查大约 200–400 单位，远低于每天 10,000 的额度。

### 2.3 中文电视和网络平台 → 半自动

TMDB 覆盖不全，豆瓣也没有开放 API，所以：
- 脚本抓取各台官网的纪录片栏目页（如央视网纪录频道、腾讯视频纪录片频道），找新出现的条目。
- 抓不到或页面改版时，在审核清单里提示，改为人工补录。

### 2.4 奖项（每年一次，不在双周周期内）

- 奥斯卡最佳纪录长片：每年 1 月公布提名，3 月颁奖
- 金马奖最佳纪录片：每年 10 月公布提名，11 月颁奖

## 3. 每两周的流程

1. **抓取**：对每个来源，查“上次检查时间 → 现在”之间的新内容。
2. **初筛（自动）**：
   - 时长门槛（YouTube）
   - 语种（英文、中文，或有英文配音）
   - 用 LLM 根据标题和简介预判主题标签，并标出疑似要排除的类型（时政、伪科学、真实犯罪等）
3. **生成待审核清单**：按来源分组，每条附带建议（收录 / 排除）和理由。
4. **人工审核**：逐条确认收录或排除。
5. **入库**：确认的条目入库；被排除的也记下来，下次不再提示。
6. **记录检查时间**：每个来源单独记，某个来源这次失败了，下次从它上次成功的时间继续。

### 条目状态

`待审核` → `已收录` / `已排除`

已公布未播出的作品另标 `待播`，播出后转 `待审核`。

---

## 4. 运行方式（实现阶段再定）

- 定时任务每两周跑一次（如 GitHub Actions 定时触发，或服务器上的定时任务）。
- 首次运行是**全量回溯**（从各来源的起始年份开始），之后才是双周增量。
- 需要的密钥：TMDB API key、YouTube Data API key（可选：LLM 的 API key，用于主题预判）。
